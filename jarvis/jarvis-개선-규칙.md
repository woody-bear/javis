_이 한 줄이 개선 우선순위 판단의 북극성이다. 단, 아래 '손대면 안 되는 것'·검증·근거 원칙은 목표보다 항상 우선한다. 이 블록을 클릭해 언제든 수정할 수 있다._

## 기본 개선사항 (공통 — 매번 이 세 가지를 먼저 점검)

1. **불필요한 중복 기능 제거** — 같은 일을 하는 코드·함수·경로가 두 곳 이상이면 하나로 통합 (동작 보존 확인 필수)
2. **에러 발생 요인 제거** — 미처리 예외, 경계 조건 누락, 실패 시 복구 부재 등 에러를 만드는 구조
3. **좀비 프로세스 생성 요인 개선** — 종료되지 않는 자식 프로세스, 해제 안 되는 타이머·리스너·락·파일핸들

## 개선 우선순위 (프로젝트 전용)

1. 메인 문서 '🔧 개선할 기능' 중 소형 항목 (죽은 코드 정리, README·주석 최신화, 문서 삭제 시 세션 정리 등)
2. 버그 — 렌더/편집/제스처 오동작의 재현 가능한 수정
3. 야간 러너·브리핑 자체의 견고성

## 🚫 손대면 안 되는 것

- 제스처 임계값·쿨다운 등 체감 튜닝 값 — 사용자 감각과 직결, 무단 변경 금지
- `docs/`·각 프로젝트 `jarvis/`의 사용자 문서 내용 (메타 json 버그 수정은 허용)
- dmg 빌드·앱 교체·재실행 (야간엔 코드 커밋까지만)
- 아키텍처 변경(webSecurity, IPC 구조 개편, app.js 대규모 모듈 분리 — 주간 작업으로)

## ✅ 검증 요구사항

- `node --check` — src/main.js, src/preload.js, src/renderer/app.js, scripts/*.js 전부
- 변경이 렌더러 UI면 관련 셀렉터가 index.html에 실제 존재하는지 grep 확인

## 근거 기준

메인 문서 개선 목록, 재현 가능한 버그, 야간 러너 로그의 실패 기록만 인정.
