# 🚀 멀티 프로젝트 운영 철학 — 머스크 모델

↰ 상위 문서: [jarvis](jarvis.md)

> 일론 머스크가 여러 회사를 동시에 발전시키는 방식을 Jarvis의 운영 원리로 삼는다. **CEO는 사용자, Jarvis는 비서실이자 공장이다.** 사용자는 결정만 하고, 조사·분석·제안·구현·기록은 시스템이 돌린다.

## 1. 포트폴리오 구조 — 프로젝트 = 회사

| 머스크 | Jarvis | 현재 상태 |
|---|---|---|
| 회사마다 하나의 미션 ("인류를 다행성 종족으로") | 프로젝트마다 **🧭 목적 한 문장** — 모든 개선은 이 문장에 다가가는가로만 판단 | ✅ 4개 프로젝트 전부 설정 |
| 회사별 독립 경영, 실패 전이 차단 | 프로젝트별 개선 규칙·금지 구역·검증 요구 분리 | ✅ `<프로젝트>-개선-규칙.md` |
| 그룹 공통 원칙 (안전·제1원리) | 공통 개선 규칙 + 절대 원칙(프로젝트 규칙으로도 못 덮음) | ✅ `공통-개선-규칙.md` |
| 위험 결정은 CEO만 (발사 승인) | 🔴 확정 게이트 — 실주문·금지 구역은 제안만, 사용자 확정 후 진행 | ✅ 추세추종 실주문 게이트 |

## 2. 하루 리듬 — 스케줄은 시스템이 지킨다

CEO가 달력을 관리하는 게 아니라, **정해진 리듬이 알아서 돌고 CEO는 결정 시점에만 등장한다.**

```
22:00  🔭 벤치마킹 러너      — "시장 조사팀": 하루 1개 회사 순환, 바깥에서 더 잘하는 사례 3단계 분석
23:00  💡 아이디어 러너      — "야간 엔지니어링 리뷰": 전 회사 코드 검토, 회사당 아이디어 최대 3건 (코드 수정 없음)
아침    🌙 야간 브리핑        — "경영 회의": 전 회사 보고가 한 화면에, 항목마다 문제→해결→효과 3문장
        🚀 착수 + 💬 코멘트  — "자원 배분 결정": 클릭 한 번 + 방향 지시 한 줄이면 구현 작업이 바로 시작
주간    구현·검증·기록        — 착수된 것만, 게이트 항목은 확정 절차 후
```

- **타임박스 강제**: 프로젝트당 12분(아이디어)·단계당 8~10분(벤치마킹), 03:30 이후 신규 시작 금지 — 회의가 늘어지지 않는 것과 같다.
- **매일 다른 안건**: 이력(bench.json)과 중복 금지 — 같은 보고를 두 번 받지 않는다.
- **결정 비용 최소화**: 착수는 10초(3문장 읽기) + 클릭. 코멘트는 선택.

## 3. 개선 판단 5단계 — 머스크 알고리즘

모든 개선 후보는 이 순서로 통과해야 한다. **순서를 건너뛰면 안 된다** (특히 1·2를 건너뛰고 3~5부터 하는 것이 최악).

1. **요구사항을 의심하라** — 그 기능/규칙이 왜 필요한가? 근거(파일:줄·로그·재현)가 없으면 요구사항 자체를 버린다.
2. **삭제하라** — 최고의 개선은 코드를 없애는 것. 중복 기능·죽은 코드·안 쓰는 옵션 제거가 항상 1순위. "나중에 10% 다시 추가하게 되지 않으면 충분히 삭제하지 않은 것."
3. **단순화하라** — 남은 것을 더 단순하게. 새 의존성·새 추상화는 단순화가 아니다.
4. **가속하라** — 단순해진 다음에야 속도(성능·응답·비용)를 올린다.
5. **자동화하라** — 마지막이 자동화다. 검증된 수동 절차만 자동화한다 (야간 러너 자신이 이 원칙의 산물).

## 4. 제1원리 사고 — 추측 금지

- 모든 제안은 **물리적 근거**까지 내려간다: 파일:줄, 재현 경로, 로그, 수치. "더 깔끔해 보여서"·"~일 수 있다"는 기각.
- 브리핑 3문장 구조(🔍 문제/🛠 해결/🎯 효과)가 제1원리 검증기다 — 셋 중 하나라도 못 쓰면 그 제안은 아직 이해가 부족한 것.

## 5. 실패 처리 — 기록하고 반복하지 않는다

- ⏸ 보류·❌ 부적합 판정은 이력에 남아 재상정되지 않는다 (같은 실패를 두 번 하지 않음).
- 야간 러너 실패는 단계별 JSON이 보존돼 다음 밤 그 지점부터 재개 — 로켓 회수·재사용과 같은 원리.
- 게이트 위반 커밋은 즉시 revert + 브리핑 최상단 ⚠️ 보고.

## 6. 다음 단계 — 아직 없는 머스크식 장치 (착수 후보)

- **주간 종합 리포트**: 일요일 밤, 한 주의 착수/완료/보류를 회사별로 집계하고 목적 문장 대비 진행도를 한 문단씩 — "이사회 보고서".
- **자원 배분 조정**: 브리핑에서 프로젝트별 우선순위(예: 이번 주는 추세추종 2배)를 지정하면 러너 순서·아이디어 수에 반영.
- **마일스톤 보드**: 각 프로젝트 '➕ 추가할 기능'에 목표일을 달고, 브리핑이 지연 항목을 자동으로 끌어올림.
- **지표 대시보드**: 목적 문장에 붙는 숫자 1개(계좌총량·테스트 수·접속자)를 매일 기록해 브리핑 상단에 추세로 표시 — "미션 계기판".
