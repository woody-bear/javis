## ➕ 추가할 기능

-   **개선 결과 확정 / 원복 선택 + 선호 수치화** _(2026-08-31 요청 · 미구현)_ — 야간에 개선된 사항마다 "확정 / 원복"을 고르고, 그 선택을 점수로 누적해 다음 개선 방향에 계속 반영하는 기능.
    -   현재 러너는 코드를 고치지 않고 아이디어만 제안하므로 "확정/원복"은 **착수/보류**에 대응하고, 실제 코드가 바뀐 뒤(주간 구현·머지 후)에는 결과에 대한 **확정/원복** 2차 판정을 추가로 받는 2단계로 설계할 예정.
    -   수치화 초안: 착수 +1 · 보류 −1 · 구현 후 확정 +2 · 구현 후 원복 −3 을 관점(angle: 안정성/운영/사용성/성능/비용…)·난이도·프로젝트별로 `~/JarvisHub/night/bench/preference.json`에 누적 → 야간 프롬프트에 "선호 관점 상위 N / 기피 관점" 으로 주입하고, 이 문서 상단에 점수 표를 자동 갱신.
-   **착수 뒤 다음 행동 연결** — 착수 알림에 "지금 구현 지시" 버튼을 붙여 해당 프로젝트 문서 채팅에 구현 프롬프트를 바로 넣거나 자동 분석 큐에 등록 (착수만으로는 아무 코드도 바뀌지 않는다는 점이 헷갈림).

## 🔧 개선할 기능

-   **설치된 앱 빌드와 소스 불일치 감지** — 08-30 09:48 빌드에는 `jarvis-bench://` 핸들러가 없어 착수 클릭이 무시됐던 문제는 08-31 08:40 재빌드로 해결됨(설치본 asar에 `jarvis-bench` 2건 확인, I-1 착수 09:10 정상 기록). 재발 방지 개선안: 앱 시작 시 빌드 시각과 소스 최신 커밋 시각을 비교해 "업데이트 필요" 알림 · 알 수 없는 `jarvis-*://` 링크 클릭 시 안내 메시지.
-   **착수 구현 큐가 앱 메모리에만 있음** — 착수로 큐에 들어간 구현 작업(`analysisQueue`)은 앱을 끄거나 재시작하면 사라지고, 브리핑 줄은 이미 "구현 작업 시작됨"으로 바뀌어 있어 실행됐다고 오해할 수 있음. 개선안: 큐를 `~/JarvisHub/night/bench/queue.json`에 저장하고 앱 시작 시 이어서 실행, 미실행 항목은 브리핑 줄에 "⏳ 대기 중" 표시.
-   **🔴 확정 게이트 항목의 확정 → 실행 경로가 수동** — I-1처럼 게이트 항목은 착수해도 등재만 되고, 채팅에 "확정 I-1"이라고 직접 써야 진행됨. 개선안: 게이트 항목의 브리핑 줄에 "🔓 확정하고 실행" 버튼을 붙여 확인 팝업 후 같은 구현 큐로 넣기.
-   **⏸ 보류와 ❌ 거부의 역할 정리** _(2026-08-31 질문 반영)_ — 브리핑에는 세 가지가 섞여 있습니다. ① 사용자 버튼 **⏸ 보류**(아이디어 I-n·벤치 B-n 대상, `jarvis-bench://hold`) → bench.json `held`, 줄이 "⏸ 보류됨"으로 바뀜. ② 사용자 버튼 **❌ 거부**(🧩 도구 추천 대상, `jarvis-reco://reject`) → recos.json `rejected`, 설치 안 함. ③ 야간 에이전트의 **판정** 문구(✅ 추천 · ⏸ 보류 · 🔴 확정 필요 · ❌ 부적합)는 AI가 스스로 내린 평가이며, ❌ 부적합은 버튼 없이 자동 `rejected` 처리됩니다. **문제**: 보류는 "나중에"라는 뜻인데 재개 버튼이 없어 실질적으로 거부와 같고, 거부된 도구는 다음 추천 프롬프트에서 제외되지 않아 같은 도구가 다른 날 다시 추천될 수 있음. **개선안**: 보류 항목에 "🔁 다시 검토" 버튼(`held → pending`) 추가 · 거부/설치된 도구 이름을 추천 프롬프트의 제외 목록에 주입 · 보류/거부 선택을 위 선호 수치화의 입력으로 사용.
-   **착수 후 진행 상태 추적** — 착수(등재)만 되고 실제 구현 여부는 아무도 추적하지 않음. 메인 문서 "➕ 추가할 기능"의 `[벤치 …]` 항목이 "✅ 완성된 기능"으로 옮겨지면 bench.json 상태를 `implemented`로 승격하고, 위 선호 수치화의 2차 판정(확정/원복) 대상으로 올리기.
